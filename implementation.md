# MEXT Physics Study Website — Implementation Plan

## Overview

An interactive, static Astro website from `MEXT_Physics_Undergrad_Master_Study_Guide.md` (1426 lines, 46 topics, 95 worked exam problems). Users can study by topic, practice problems, drill flashcards, take quizzes, and track progress — all without a backend.

---

## 1. Tech Stack

| Layer | Choice | Rationale |
|-------|--------|-----------|
| **Framework** | [Astro](https://astro.build) v4 | Content-first SSG, native Markdown support, zero JS by default |
| **Interactive Islands** | Preact | Tiny footprint (3 kB) for client-side components |
| **Content Collections** | Astro `content/` (data layer) | Typed schemas, build-time validation, automatic `getCollection()` |
| **Formula Rendering** | KaTeX | Fastest math renderer, outputs static HTML at build time |
| **Search** | Fuse.js (client-side) | Lightweight fuzzy search on pre-built JSON index |
| **Styling** | CSS Custom Properties | No framework overhead; dark mode via `prefers-color-scheme` + toggle |
| **State** | `localStorage` | No backend; progress persists across sessions |
| **Deployment** | Static (Netlify / Vercel / Cloudflare / GitHub Pages) | Zero infrastructure |

## 2. Data Model

Parsed from the markdown at build time into Astro content collections.

```
content/
  topics/
    t01.json
    t02.json
    ...
    t46.json
```

### Schema (all topics validated by `astro:content`)

```typescript
interface Topic {
  id: string;           // "t01"
  number: number;       // 1–46
  title: string;        // "Uniform Acceleration & v–t Graphs"
  part: string;         // "Mechanics"
  partNumber: number;   // 1–5
  anchor: string;       // "t01"
  theory: string;       // Markdown body
  formulas: { latex: string; description: string }[];
  framework: string[];  // Problem-solving steps
  problems: Problem[];
  tags: string[];
  theoryOnly: boolean;
}

interface Problem {
  examRef: string;      // "2016-UG-Q1-(1)"
  year: number;
  parts: {
    partNum: number;
    parameters: string;
    formulas: string;
    calculations: string;
    answer: string;
    conclusion: string;
  }[];
}
```

## 6. Build-Time Pipeline

```
raw.md
   │
   ▼
scripts/parse-markdown.js
   │  Uses remark + custom parsers
   │
   ├──→ src/content/topics/t01.json … t46.json
   │     Astro content collections validate each
   │
   └──→ public/data/search.json
         Fuse.js index for client-side search
```

### Parser Strategy (per topic block)

1. Split on `## Topic N — Title` boundaries
2. Extract `**Theory.**` → `theory`
3. Extract `**Key Formulas**` → `formulas[]`
4. Extract `**Problem-Solving Framework**` → `framework[]`
5. Extract problem blocks via `#### Problem YYYY-UG-QX-(N)` anchors:
   - Parse labelled sections: `**Parameters**`, `**Formulas needed:**`, `**Calculations:**`, `**Answer:**`, `**Conclusion:**`
6. Skip `---` separators and non-topic sections (Appendices, speed rules, constants)

## 7. Interactive Features

### Flashcards (SM-2 Spaced Repetition)

- **Source material:** Auto-generated from formulas, framework steps, problem conclusions, key insights
- **SM-2 algorithm:** each card has `(interval, ease, repetitions, nextReview)` in localStorage
- **Session flow:** review cards due today → optional new cards → shuffle → rate each
- **Component:** `<FlashcardDeck client:visible />`

### Problem Reveal

- Each problem part begins collapsed
- User clicks progressive buttons: "Show Parameters" → "Show Formulas" → "Show Calculations" → "Show Answer" → "Show Conclusion"
- All content already exists in the parsed JSON — no generation needed
- **Component:** `<ProblemReveal client:idle />`

### Quiz Mode

- Draws from the 95 worked problems
- MCQ format: correct answer + 4–5 distractors (generated from other options in the same paper)
- Configurable: by part, by topic, by year, random, or "weak areas only"
- Timed at ~2.5 min per question (matching exam pace)
- **Component:** `<QuizPanel client:visible />`

### Progress Tracking

- Stored in `localStorage` under key `mext-physics-progress`
- Schema:
  ```typescript
  interface Progress {
    topics: Record<string, TopicProgress>;
    sessions: SessionRecord[];
    quizHistory: QuizResult[];
    flashcardStats: FlashcardStats;
    streak: { current: number; longest: number; lastDate: string };
    settings: UserSettings;
  }
  ```
- Topic progress: `{ status: 'new' | 'studying' | 'reviewing' | 'mastered', problemsRevealed: number, quizCorrect: number, timeSpent: number }`
- Export/import as JSON file

## 10. Notes & Risks

- **Formula complexity:** The markdown uses inline `$...$` and block `$$...$$` LaTeX. KaTeX handles both — ensure `\` is properly escaped in JSON.
- **HTML in markdown:** The file uses `<a id="t01"></a>` anchors, `<br>`, `---` horizontal rules. The parser must handle these gracefully.
- **Unicode:** Japanese characters (物理, がんばってください), Greek letters, arrows — verify encoding throughout.
- **Build-time parsing:** The `parse-markdown.js` script runs via `astro build` (as a `beforeBuild` hook or standalone node script). Parsed JSON is committed to the repo for CI/caching.
- **Edge cases:** Topics marked `[theory only]` (no worked problems), appendices with answer keys and constants, table-based content in the topic index.
